# Kotori Mail Bird v0.2.0

Release date: 2026-08-02

## Scope

Version 0.2.0 completes the move from the legacy database and queue stack to managed Convex. The release uses the existing Convex project `kotori-db`; it must not create a replacement project during setup or deployment.

The release also standardizes development, CI, and container builds on pnpm 11.18.0 with Node.js 22.13 or newer. Dependency policy forces the patched `sharp` 0.35.3 and `postcss` 8.5.25 versions, and repository automation now includes Dependabot and CodeQL.

## Rollout status

- Convex project: existing `kotori-db` project documented and retained.
- Application release metadata: version 0.2.0.
- Live VPS frontend/Caddy rollout: deferred; no live deployment is claimed by this release preparation.

## Deferred VPS checklist

Complete these steps only after deployment approval:

1. Confirm the production Convex environment variables and deploy the backend with `pnpm convex:deploy`.
2. Back up the current VPS environment and preserve `CREDENTIAL_ENCRYPTION_KEY` in the approved encrypted secret manager.
3. Populate `.env.production` from `.env.production.example` without committing secrets.
4. Build with `docker compose --env-file .env.production -f compose.production.yml build`.
5. Start with `docker compose --env-file .env.production -f compose.production.yml up -d`.
6. Verify `https://<production-domain>/api/health`, authentication, mailbox connection, draft creation, and the absence of send capability.
7. Record the deployment time, image identity, health evidence, and rollback decision.

Until that checklist is approved and completed, the VPS commands in the README are a runbook only.
